# Recording schema and timestamp semantics

All timestamps are SI seconds in the Gazebo simulation domain unless explicitly named active_time_s/time_active_s. Worker request `time=t` contains current robot pose and finite-difference velocity measured over the previous planning interval. `before` is human state at t; `humans` is the future proposal at state_time=t+0.1. The response adapter linearly interpolates XY and shortest yaw within this interval at physics dt=0.0025. A worker endpoint is not proof of Gazebo execution.

`native/episode/gazebo_poses.jsonl` is authoritative sampled observed proxy pose, with timestamp `time`; only rows after the accepted goal gate and with all six proxies and the robot are normalized. `pose_timeline.jsonl` copies these XY/yaw values exactly. `human_states.jsonl` has one row per human per observed tick. Velocity and displacement use backward finite differences over actual pose sample dt; the first observed sample has null velocity. Native proposals/post-ORCA/post-projection are stage signals from the containing worker interval identified by stage_interval_start, not measured Gazebo velocities. Group membership is from the interval's groups_before. Goals come from the simulation-clock snapshot; assignment occurs at interval start. Goal-progress calculations exclude segments whose target changes.

`native_preferred_velocity` in the first baseline/revision1 normalized files maps to motion_contract.native_proposed_velocity, i.e. native tentative displacement/dt after integration/capping, NOT a raw pre-noise preferred velocity. Revision2 uses the accurate name native_proposed_velocity. This field mapping does not change original records. Unprocessed individual native ORCA preference is NOT MEASURED. The original stage field remains native_proposed_velocity in worker JSONL for every version.

The `constraints` field is the full projection audit including margin attempts, feasibility, reachability and predicted swept gaps. Exact active support-plane multipliers are NOT MEASURED. `behavior_state` and `partner` are null for baseline because no such state machine existed. No state is invented from baseline speed. Group envelopes/centroids/member distances are reconstructed from observed poses and current recorded membership; preferred group motion is in raw native_group_intent/group_intent or behavior.groups, not an observed velocity.

`robot_inputs.jsonl` preserves every actual worker request including warmup. Its vx/vy/omega are finite differences over the previous 0.1s; Gazebo robot pose samples remain in original gazebo_poses.jsonl. Controller replay at endpoint t+dt aligns to the NEXT recorded robot request. Its single last future robot endpoint is extrapolated with measured velocity and is explicitly identified; results are reported separately from observed clearance. The original revision1 analyzer's one-interval robot misalignment is preserved and invalidated in comparison/ANALYSIS_CORRECTION.md. Authoritative corrected results are comparison_final/.

`behavior_events.jsonl`: controller events carry time_active_s relative to the first active controller step and worker_time in absolute simulation time. This offset differs from goal gate time by up to one planner interval. Clock events carry time_sim_s. Proximity events use actual sample time and mean sampled surface gap <0.8m; they do not prove intentional avoidance. State occupancy counts labels, not successful maneuver outcomes. The same persistent side may remain safety-overridden by ORCA/projection. No passing_side_change is fabricated when none occurs.

The revised opt-in projection uses robot radius 0.37m (physical 0.25 + 0.12 buffer). Raw guard predicted_clearance.robot is residual against this inflated radius. comparison_final/ converts it to the COMMON physical 0.25m disc; raw residual and conversion provenance are retained. Human radius 0.36m and exact 42 Warehouse AABBs are unchanged. Pose-segment swept clearance assumes linear motion between samples, not full rotating mesh or unobserved contact verification.

Native recording is sampled telemetry, NOT every 400Hz physics pose; planner intentions are recorded every 10Hz controller tick. Body articulation/gaze, force/contact data, perceived sensor input, reaction latency, exact active constraints, empirical human-realism score, and baseline behavior-state categories are NOT MEASURED. Heading error, acceleration and event timestamps are documented measurement definitions, not empirically calibrated human thresholds.

Component fixtures run the real SocialDiversity + ResponsiveMotion ORCA/projection at dt0.1 with declared geometry in config.json and one/two/three real native human objects. Their native lifecycle callback is intentionally a no-op; they test motion/interaction logic only. Their endpoints are COMPONENT, not Gazebo ground truth. Standing conversation is only demonstrated in this component sense. All 20 raw files are retained.

Recorded-pose GIFs resample actual Gazebo pose timelines at 5Hz with shortest-yaw interpolation. Native live runs are aligned by first active observed pose for side-by-side review; different duration/robot inputs mean these GIFs are NOT causal A/B. A finished trace visibly holds its last frame. Baseline GIF retained from the first render includes its labelled hold tail. No MP4 was generated; ffmpeg was absent. Runtime camera_preview_4x.gif is actual onboard camera output, accelerated 4x by the existing capture infrastructure, not the 2D human playback or proof of 3D human visual quality.
